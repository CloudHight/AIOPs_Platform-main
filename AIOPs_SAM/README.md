# AIOPs_SAM Setup Guide

This folder contains the custom AWS SAM files for the AIOps anomaly detection and auto-remediation service.

These files are used to replace the default files generated by a fresh AWS SAM project scaffold.

## Files in this folder

- `app.py`: the custom Lambda application logic for anomaly detection, Jira ticket creation, notifications, and remediation
- `template.yaml`: the custom SAM infrastructure template for the Lambda function and supporting AWS resources
- `samconfig.toml`: the deployment configuration and parameter defaults for the SAM project

## How to use these files in this project

### 1. Switch into the `AIOPs_SAM` directory

```bash
cd AIOPs_SAM
```

### 2. Initialize a new SAM project

Run:

```bash
sam init
```

When prompted:

- select the `Hello World Example` template
- enable the default recommended options such as X-Ray tracing, CloudWatch monitoring, and the other default SAM settings
- set the project name to:

```text
aiops-test
```

This creates a new SAM project folder named `aiops-test`.

### 3. Move into the generated project

```bash
cd aiops-test
```

### 4. Remove the default SAM files

Delete the default generated files:

```bash
rm samconfig.toml template.yaml
```

### 5. Copy in the custom SAM files from `AIOPs_SAM`

Run:

```bash
cp ../samconfig.toml .
cp ../template.yaml .
```

This replaces the default SAM configuration and infrastructure definition with the project-specific versions.

### 6. Rename the Lambda source folder

Rename the generated `hello_world` folder to `src`:

```bash
mv hello_world src
```

### 7. Replace the default Lambda application file

Copy the custom `app.py` from `AIOPs_SAM` into the new `src` folder:

```bash
rm src/app.py
cp ../app.py src/app.py
```

This makes the Lambda function use the custom anomaly detection logic from this project instead of the default sample handler.

## Files after replacement

After the file replacement steps:

- `src/app.py` contains the custom Lambda logic
- `template.yaml` defines the AWS resources used by the AIOps system
- `samconfig.toml` contains deployment defaults and parameter overrides

## Update configuration before deployment

Before building and deploying, review and update the values in `samconfig.toml`.

You should update values such as:

- `AnomalyScoreThresholdCPU`
- `AnomalyScoreThresholdLog`
- `NotificationEmail`
- `CPUAnomalyModelEndpoint`
- `LogAnomalyModelEndpoint`
- `JiraProjectKey`
- `MonitoringFrequency`
- `InstanceTagKey`
- `InstanceTagValue`

You should also review `template.yaml` and update the Jira credentials placeholder values, especially:

- Jira user email
- Jira API token

Do not deploy using placeholder values.

## Build the project

After the configuration is updated, run:

```bash
sam build
```

Wait for the build to complete successfully.

## Deploy the project

Then run:

```bash
sam deploy
```

When prompted to approve deployment, enter:

```text
y
```

## End-to-end workflow summary

1. `cd AIOPs_SAM`
2. `sam init`
3. choose `Hello World Example`
4. enable the default options like X-Ray and CloudWatch
5. name the project `aiops-test`
6. `cd aiops-test`
7. remove the default `samconfig.toml` and `template.yaml`
8. copy in `samconfig.toml` and `template.yaml` from `AIOPs_SAM`
9. rename `hello_world` to `src`
10. replace `src/app.py` with `AIOPs_SAM/app.py`
11. update `samconfig.toml` and `template.yaml` with your real values
12. run `sam build`
13. run `sam deploy`
14. enter `y` when prompted to approve deployment

## Notes

- The custom `template.yaml` expects the Lambda code folder to be named `src`.
- The custom `app.py` depends on the resources and environment variables defined in `template.yaml`.
- The values in `samconfig.toml` should be treated as environment-specific and reviewed before every deployment.
